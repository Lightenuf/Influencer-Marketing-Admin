2026-09-26 기준. 아임웹 REST API v2로 받아 `~/imweb_crm.db`(내 맥에만 있는 파일)에 담았다.
받은 원본 JSON을 그대로 보관하고, 자주 쓰는 값만 따로 칸으로 빼 두었다.

받는 방법은 `~/imweb_sync.py`. 다시 받으려면 아래처럼 한다.

```bash

```

- **성별 83.6%(793명) · 생일 99.9%(948명)** — 생일 쿠폰이나 성별 타겟은 지금도 가능하다

## 문제가 되는 것 — 먼저 확인이 필요합니다

### 1. 마케팅 수신동의가 949명 전원 '아니오'

`marketing_agree_sms`, `marketing_agree_email`, `third_party_agree` 세 항목 모두
**949명 전부 N**이다. 값을 잘못 읽은 게 아니라 아임웹이 그렇게 주고 있다.

이대로면 **문자·이메일을 보낼 수 있는 대상이 0명**이다.
가입 폼에 수신동의 항목이 없거나, 체크해도 저장되지 않고 있을 가능성이 크다.
아임웹 관리자에서 회원가입 항목 설정을 먼저 봐야 한다.

### 2. 주문의 75%가 비회원이다

아임웹은 비회원 주문에도 `gu`로 시작하는 임시 코드를 준다. 회원 코드(`m`으로 시작)와
구분해서 세면 이렇다.

- 회원 주문 573건 · 비회원 주문 1,709건
- 주문한 회원 476명 (전체 회원 949명의 50.2%)
- 재구매 회원 70명 (회원 주문 2회 이상)

비회원 주문 대부분은 외부 채널에서 들어온 것으로 보인다.
주문의 판매 채널 값이 `2`인 것이 1,671건이고, 외부 채널 주문번호가 붙은 것이 1,683건이다.
**이 1,700여 건은 이름과 연락처는 있지만 회원이 아니라, 회원 기준 조건으로는 잡히지 않는다.**

### 3. 유입 경로와 카카오 친구 정보는 없다

이름에 유입 관련 낌새가 있는 항목을 전부 훑었지만 쓸 만한 것이 없었다.

- `members.recommend_code`, `recommend_target_code` — 추천인 항목은 있으나 **949명 전원 비어 있다**
- `orders.sale_channel_idx`, `channel_order_no` — 자사몰인지 외부 채널인지 구분만 된다
- **카카오 친구 여부를 알 수 있는 항목은 아예 없다**

카카오 친구를 조건으로 쓰려면 채널톡이나 카카오 싱크 쪽 자료가 따로 필요하다.
지금 채널톡을 쓰고 계신지, 카카오 싱크가 연결되어 있는지 알려주시면 가능한지 확인해 보겠습니다.

## 어드민으로 옮기기

받아 둔 자료는 내 맥의 파일이라 웹 어드민이 읽지 못한다. 옮겨야 화면에 숫자와 명단이 나온다.

1. Supabase SQL 편집기에서 `0024_customers.sql`, `0025_preview_customer_group.sql` 실행
2. Supabase 설정 > API 에서 `service_role` 키를 복사해 키체인에 한 번 넣는다

   ```bash
   security add-generic-password -a $USER -s SUPABASE_URL -w
   security add-generic-password -a $USER -s SUPABASE_SERVICE_KEY -w
   ```

3. 옮긴다

   ```bash
   python3 ~/imweb_to_supabase.py
   ```

자료가 바뀌면 `imweb_sync.py` 로 다시 받고 이 스크립트를 한 번 더 돌리면 된다. 같은 사람은 덮어쓴다.

### 무엇이 올라가나

- 회원 949명 + **비회원 주문자 1,526명** = 2,475명. 비회원을 빼면 실제 구매자 대부분이 보이지 않는다
- 취소·반품을 뺀 주문 2,068건
- 사람마다 미리 계산해 둔 구매 횟수·누적 금액·마지막 구매일·산 상품·쓴 쿠폰

조건으로 세는 일은 Supabase 안의 함수(`preview_customer_group`)가 한다.
세는 규칙이 한곳에 있어야 화면에 보이는 숫자와 내려받은 명단이 어긋나지 않는다.

접근 제한은 인플루언서 자료와 같다 — **로그인한 팀원만** 조회할 수 있고, 로그인하지 않으면 아무것도 나오지 않는다.

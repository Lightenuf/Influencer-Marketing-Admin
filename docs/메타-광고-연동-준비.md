# 메타 광고 연동 — 준비와 설계

어드민에 메타(Facebook·Instagram) 광고 기능을 붙이는 작업의 현재 상태와, 실제 광고 계정에
연결하기 위해 메타 쪽에서 해둬야 할 일을 적어둔다.

## 지금 상태

| 기능 | 상태 |
|---|---|
| 광고 대시보드 | 화면 완성 · **예시 데이터**로 동작 |
| 소재 성과 (계층 목록 + 추세선) | 화면 완성 · **예시 데이터**로 동작 |
| 소재 업로드 | 아직 |
| 기존 광고 관리 (예산 · On/Off) | 데이터 계층만 준비 |

화면 오른쪽 위에 `예시 데이터 — 메타 계정에 아직 연결되지 않았습니다` 딱지가 보이면
가짜 숫자를 그리고 있는 것이다. 연결되면 딱지가 사라진다.

## 왜 서버가 필요한가

이 어드민은 **브라우저에서만 도는 정적 사이트**(GitHub Pages)다. 반면 메타 System User 토큰은
광고 계정의 예산까지 바꿀 수 있는 열쇠라, 브라우저에 두면 누구나 개발자 도구로 꺼내 쓸 수 있다.

그래서 토큰을 쥐고 메타를 대신 호출해 줄 자리가 하나 필요하다. **Supabase Edge Functions**를
쓰기로 했다 — 이미 쓰는 Supabase 안에서 끝나고, 기존 로그인으로 호출 권한을 막을 수 있으며,
지표를 미리 받아두는 배치도 같은 곳에서 돌릴 수 있다.

```
브라우저(어드민)  →  Supabase Edge Function  →  메타 마케팅 API
   로그인한 팀원만      토큰은 여기에만 있음        광고 계정
```

배포 방식(GitHub Pages)은 그대로 둔다.

## 코드가 갈라지는 지점

화면은 `MetaRepository` 하나만 알고 있고, 그 뒤가 예시 데이터인지 실제 메타인지 모른다.

| 파일 | 하는 일 |
|---|---|
| `src/data/metaTypes.ts` | 캠페인·광고 세트·광고·지표 모양과 ROAS·CPC 같은 계산 |
| `src/data/metaRepository.ts` | 화면이 쓰는 창구(인터페이스) |
| `src/data/metaMockAdapter.ts` | 예시 데이터 — 연결되면 쓰이지 않는다 |
| `src/data/index.ts` | `VITE_META_PROXY_URL`이 있으면 실제 연동으로 바꾼다 |

실연동은 `metaApiAdapter.ts`를 추가해 갈아끼우기만 하면 되고, 화면 코드는 건드리지 않는다.

## 메타 쪽에서 해둬야 할 일

### 1. Business Manager · 광고 계정 (완료)

회사 계정(marketing@lightenuf.com)이 Business Manager의 Admin이고, 광고 계정이 그 소유여야 한다.

### 2. 앱 등록

1. [developers.facebook.com](https://developers.facebook.com) → 내 앱 → 앱 만들기
2. 유형은 **비즈니스**
3. 만든 앱을 Business Manager에 연결 (비즈니스 설정 → 계정 → 앱)
4. 제품 추가에서 **마케팅 API** 사용 설정

> 앱 ID와 앱 시크릿이 나온다. **시크릿은 채팅이나 문서에 붙여넣지 말 것** — 서버 설정에만 넣는다.

### 3. System User 토큰 발급

사람 계정에 딸린 토큰은 그 사람이 퇴사하거나 비밀번호를 바꾸면 끊긴다. System User는 사람이 아닌
'프로그램용 계정'이라 만료가 없다.

1. 비즈니스 설정 → 사용자 → **시스템 사용자** → 추가
2. 이름 예: `breevo-admin-api`, 역할은 **관리자**
3. 만든 System User에 **자산 추가**
   - 광고 계정 → 권한: 광고 관리
   - 페이지 → 권한: 콘텐츠 관리
   - Instagram 계정 → 권한: 관리
4. **새 토큰 생성** → 앱은 2번에서 만든 앱 선택 → 권한(스코프) 체크
   - `ads_management` (광고 만들기·수정)
   - `ads_read` (지표 조회)
   - `business_management`
   - `pages_show_list`, `pages_read_engagement`
   - `instagram_basic`
5. 나온 토큰을 **한 번만 보여주므로 바로 안전한 곳에 저장**

> 토큰은 저에게 보내지 마세요. Supabase 대시보드 → Edge Functions → Secrets에 직접 넣으시면 됩니다.
> 넣어야 할 이름은 연동 작업을 시작할 때 알려드리겠습니다.

### 4. 전환 추적 · 도메인 인증

매출·ROAS·전환율이 맞으려면 이미 되어 있어야 하는 것들이다.

- 랜딩 페이지에 **픽셀** 또는 **Conversions API**가 붙어 있고 구매 이벤트가 잡히는지
- 랜딩 도메인이 Business Manager에서 **도메인 인증**되어 있는지 (iOS 이후 이게 없으면 전환이 샌다)

### 5. 파트너십 광고 (소재 업로드 기능에 필요)

자주 협업하는 크리에이터와 **계정 레벨 파트너십 권한**을 미리 연결해 두면, 소재마다 크리에이터의
개별 승인을 받지 않아도 광고를 돌릴 수 있다. 연결이 안 된 크리에이터는 게시물마다 권한 코드를
받아야 해서 자동화가 끊긴다.

## 아직 정해야 하는 값

소재 업로드 기능을 만들기 전에 확정이 필요하다. "매번 설정하지 않아도 되게" 하려면 기본값이
정해져 있어야 하기 때문이다.

- ~~**오브젝티브**~~ → **확정**: 기본은 판매(OUTCOME_SALES), 다만 화면에서 고를 수 있게 한다.
  트래픽·참여로 돌릴 때가 있기 때문. (`META_OBJECTIVES` in `src/data/metaTypes.ts`)
- **전환 이벤트**: 구매(Purchase)인지 장바구니 담기인지.
  판매 목표에서만 필요하고, 픽셀에 구매가 주당 50건쯤 쌓여야 학습이 제대로 돈다.
- **CTA 버튼**: 목표별로 기본값을 미리 넣어뒀다(판매 → '지금 구매하기', 트래픽·참여 → '더 알아보기').
  바꿀 것이 있는지 확인 필요.
- **랜딩 URL**: 항상 같은 주소인지, 소재마다 다른지
- **기본 타겟**: 신규 광고 세트를 만들 때의 연령·성별·관심사 기본값
- **지표 갱신 주기**: 1시간마다 · 3시간마다 · 하루 한 번 중 어느 쪽인지

## 남은 작업 순서

1. **(지금)** 대시보드 · 소재 성과 화면 — 예시 데이터로 완료
2. Edge Function + 실데이터 연결 (토큰 준비되면)
3. 기존 광고 관리 — 예산 조정 · On/Off
4. 소재 업로드 — 배치 업로드 · 프리셋 · 신규 캠페인/광고 세트 생성

3번을 2번 바로 뒤에 두는 이유는, 읽기만 하다가 쓰기로 넘어가는 첫 단계라 작게 시작해
토큰 권한과 연동이 제대로 되는지 확인하기 좋아서다.

## 유의할 점

- **예산은 광고에 붙지 않는다.** 메타에서 예산은 광고 세트(캠페인 예산 최적화면 캠페인)에 있다.
  화면에서 광고 단위로 조정하더라도 실제로는 상위 광고 세트의 값을 바꾼다.
- **카탈로그(다이내믹 프로덕트) 광고는 만들지 않는다.** 표준 이미지·영상 크리에이티브로 고정하고,
  카탈로그 선택은 화면에 두지 않는다.
- **큰 영상 업로드.** Edge Function은 요청 크기와 실행 시간에 한계가 있어 큰 영상을 그대로
  통과시키기 어렵다. 브라우저에서 Supabase Storage로 올린 뒤 서버가 메타로 넘기는 방식이 안전하다.
- **호출 한도.** 메타 API에는 한도가 있어 지표를 매번 새로 부르면 막힌다. 지금도 받아온 값을
  5분간 그대로 쓰고 있고, 실연동에서는 배치로 미리 받아두는 방식을 쓴다.

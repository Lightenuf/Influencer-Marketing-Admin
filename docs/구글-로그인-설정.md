# 회사 구글 계정으로 로그인하기 — 설정 절차

어드민 로그인 화면에 `회사 구글 계정으로 로그인` 버튼이 있다.
버튼은 이미 들어가 있고, 아래 설정을 마쳐야 실제로 동작한다.

## 왜 바꾸는가

이메일·비밀번호 방식은 두 가지가 약하다.

- 실제로 없는 주소(`abc@lightenuf.com`)로도 가입을 시도할 수 있다
- 퇴사자 계정을 어드민에서 따로 찾아 꺼야 한다

구글 로그인은 **회사 Google Workspace 계정이 없으면 아예 들어올 수 없고**, Workspace에서 계정을
끄면 어드민 접근도 같이 끊긴다. 비밀번호를 따로 관리할 일도 없다.

## 1. 구글 쪽 — OAuth 클라이언트 만들기

1. [Google Cloud Console](https://console.cloud.google.com/) → 프로젝트 만들기 (이름 예: `breevo-admin`)
2. **API 및 서비스 → OAuth 동의 화면**
   - User Type: **내부(Internal)** 를 고른다.
     Workspace 조직 계정만 쓸 수 있게 되어, 이것만으로도 외부인이 막힌다.
   - 앱 이름: `Breevo 마케팅 허브`, 지원 이메일: 회사 주소
3. **API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**
   - 유형: **웹 애플리케이션**
   - **승인된 리디렉션 URI**에 아래를 넣는다 (Supabase가 알려주는 주소와 같아야 한다)

     ```
     https://xfqvlkocdutsqrrbmvnk.supabase.co/auth/v1/callback
     ```

4. 만들면 **클라이언트 ID**와 **클라이언트 보안 비밀**이 나온다.
   → 이 값은 채팅에 붙여넣지 말고 다음 단계에 바로 넣는다.

## 2. Supabase 쪽 — 구글 로그인 켜기

1. Supabase 대시보드 → **Authentication → Sign In / Providers**
2. **Google** 을 켠다
3. 1번에서 받은 **Client ID**와 **Client Secret**을 넣고 저장
4. 같은 화면에서 **Confirm email** 도 켜 둔다 (이메일·비밀번호 로그인을 남겨두는 동안 필요하다)

## 3. 돌아올 주소 등록

Supabase 대시보드 → **Authentication → URL Configuration**

- **Site URL**: `https://lightenuf.github.io/Influencer-Marketing-Admin/`
- **Redirect URLs** 에 아래 둘을 넣는다

  ```
  https://lightenuf.github.io/Influencer-Marketing-Admin/**
  http://localhost:5173/**
  ```

여기에 없는 주소로는 로그인 후 돌아올 수 없다. 나중에 회사 도메인을 붙이면 그 주소도 더한다.

## 4. 확인

1. 어드민 로그인 화면에서 `회사 구글 계정으로 로그인`
2. 회사 계정으로 들어가 대시보드가 보이면 성공
3. 개인 지메일로도 한 번 시도해 본다 → **막혀야 정상이다**

막히지 않는다면 1번의 User Type이 `내부`가 아니거나, DB 트리거(`0002_restrict_signup_domain.sql`)가
실행되지 않은 것이다.

## 나중에 — 이메일·비밀번호 없애기

팀원이 모두 구글 로그인으로 옮겨오면 이메일·비밀번호 방식을 지우는 편이 낫다.
지킬 것이 하나 줄어든다. 옮겨온 뒤 알려주면 로그인 화면에서 덜어낸다.
